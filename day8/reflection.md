# Day 8 Reflection

The most difficult concept for me in this course was understanding how a system can handle many requests simultaneously without creating data inconsistencies. Designing TicketHub helped me understand why database transactions, conditional updates, and constraints are important when several customers attempt to purchase the same seat. I worked through this challenge by breaking the process into smaller steps and examining how the database should respond when two customers request the same seat.

One part of my capstone that I would improve is the system architecture explanation. I would make the request flow clearer and explain more precisely how the waiting room, application servers, and database work together during a popular ticket sale. I would also use feedback from my instructor or peers to identify any remaining weaknesses and improve the design.

Next, I want to learn more about PostgreSQL and backend API development using Node.js and Express. Understanding how to implement database transactions, enforce constraints, and handle payment requests would help me move from designing systems to building reliable applications. I also want to practise load testing so that I can measure system performance and identify bottlenecks instead of relying only on estimates.
